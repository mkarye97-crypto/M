# MOODY QUREO — نسخة الويب لـ Railway

## التشغيل المحلي
```bash
pip install -r requirements.txt
export SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
python app.py
```

## النشر على Railway
1. ارفع محتويات هذا المجلد إلى GitHub repository (المجلدات `levels/` و`data/` وملفات `main.py` و`assessment_runner.py` مهمة).
2. في Railway أنشئ مشروعًا من GitHub repository.
3. أضف Variable باسم `SECRET_KEY` بقيمة عشوائية قوية لا تقل عن 32 حرفًا. لا تضعها في GitHub.
4. أمر التشغيل:
   `gunicorn app:app --workers 1 --threads 4 --timeout 120`
5. انتظر نجاح Healthcheck على `/health`.

## ملاحظات مهمة
- التطبيق الآن واجهة ويب Flask؛ لا تستخدم `python main.py` كأمر تشغيل على Railway. هذا الملف CLI ويطلب إدخالًا تفاعليًا، وهو سبب EOFError.
- كلمة مرور الطالب لا تُكتب في ملفات أو سجلات التطبيق. تبقى جلسة QUREO في ذاكرة العملية فقط، وتُمسح عند تسجيل الخروج أو إعادة تشغيل الخدمة.
- استخدم عامل Gunicorn واحدًا لأن جلسات QUREO وحالة المهمة محفوظتان في الذاكرة. لا تضف أكثر من worker.
- ابدأ بوضع المعاينة. التشغيل الفعلي يحتاج موافقة واضحة داخل الصفحة وقد يرسل إجابات ويغيّر تقدم الحساب.
- بنك الإجابات مصدر خارجي غير رسمي؛ نتيجة QUREO وحدها تؤكد صحة الإجابة. لا توجد ضمانة لاكتمال كل فصل.
- لم يُختبر تسجيل دخول حي إلى QUREO؛ لا ترفع بيانات حسابك إلينا ولا ترسل كلمة المرور في المحادثة.
- العلامة النصية "مكاري — المطوّر" مضافة في الواجهة. احتفظ بإشعارات تراخيص أي مكونات خارجية إن وجدت.
